## #5 Wallat et al. 2024 — Correctness is not Faithfulness in RAG Attributions (ECIR/arXiv 2412.18004)

- **能复用什么**：核心可搬走的是它的 **adversarial statement-injection 协议**——把模型已生成答案中的 statement（平均 2–4 token）追加到三类文档（random / relevant-but-not-cited / cited-for-other-reason）里，重新生成，看模型是否改引被污染文档；这正是我们 NIAH 反事实 "Source-A" 干扰项构造的一个 citation 侧镜像，可以直接引用它来论证「靠 token-matching 的 citation 不可信，所以需要检索侧的 cross-source 信号」。另外它提出的 citation faithfulness 三条件定义（a_j∈A、supported/correctness、causally impacted）和四项 desiderata（Correctness / Appropriateness / Comprehensiveness / Faithfulness，Table 1）是写 related work 时干净的概念框架；它明确建议 "faithful model should either cite itself or omit a citation"——这句可直接引来给我们的 parametric vote（模型自身知识作为一票显式来源）做理论背书。
- **精确实验协议**：Model = Cohere Command-R+（104B，"RAG-optimized"，4-bit quantization，单张 A100）；dataset = NaturalQuestions 1,444 个真实用户问题 + temporally-aligned KILT Wikipedia dump；检索 = 100-token chunk（前置页面标题），BM25 top-30 → ColBERT v2 rerank → top-5 进 prompt（Cohere 官方 grounded generation template，四步：判相关→选引用→无引用答案→带引用答案）。攻击集规模：random 1,344 / relevant-not-cited 702 / cited-other-reason 829 个 QA pair；判定粒度是 statement 级（子句级短语），判定方式 = 重新生成后字符串匹配旧 statement（recover 率 63–70%）再看 adversarial 文档是否被引。无 NLI 判定器、无人工评估。
- **我的做法哪里不同**：机制层面我们不评估 citation，而是把「答案是否被多个独立来源 corroborate」前移到 reranking 阶段——它证明的是生成端 citation 会 post-rationalize（先有 parametric 答案再找 token-match 的文档），而我们的 CorroborationReranker 恰好把「parametric prior 与检索文档的一致性」变成一个显式、可数的投票信号（相同 normalized answer 的其他来源数），而不是留给 LLM 在解码时隐式决定；我们的 extraction prompt（"Using ONLY the passage"，无答案回 NONE）是对它指出的 parametric leakage 的直接工程防御。粒度也不同：它是 statement→document 的 citation 对，我们是 passage→shortest exact answer 的抽取。
- **reviewer 会攻击哪一点**：最可能的攻击是——我们的 per-passage answer extraction 本身就是一次小型生成，按本文逻辑同样可能 post-rationalize（extractor 从只含 token 匹配的段落里"抽出"其 parametric 答案），所以 "Using ONLY the passage" prompt 约束缺乏 faithfulness 验证，审稿人会要求我们做一个 Wallat 式注入实验证明 extractor 不吃 adversarial token-match；其次 parametric vote 与 corroboration vote 相关（同一模型），削弱"独立来源"叙事。反过来这篇自身的弱点也明确：单模型（仅 Command-R+）、单数据集（NQ）、statement recover 率只有 63–70% 导致分母偏差、且它自己在 Discussion 承认实验隐含假设"插入无关文档不改变模型内部状态"未经内部状态检验——引用它下结论时要写成 "evidence of"而非 "proof of" post-rationalization。

**关键数字**：① 注入 random 文档被引率 12%（116/936，Fig. 3）；② 注入 relevant-but-not-cited 文档被引率 **57%**（273/476）；③ 注入 cited-for-other-reason 文档被引率 55%（290/525）——摘要中 "up to 57% citations post-rationalized" 即出自②；④ 旧 statement 在重新生成中 recover 率 63–70%（Fig. 3 正文）；⑤ 攻击数据集规模 1,344 / 702 / 829 QA pairs（Sec. 5 Experiments）。

## #19 Wang et al. 2024 — Astute RAG: Overcoming Imperfect Retrieval Augmentation and Knowledge Conflicts (arXiv 2410.07176)

- **能复用什么**：三个可直接搬走的实验设计：(1) **retrieval-precision 分桶分析**（Fig. 7）——把测试集按 per-query retrieval precision 分桶画性能曲线，我们可以对 NIAH 任务按「反事实干扰项占 top-k 比例」做同款图；(2) **conflict 三分子集分析**（Fig. 8）——按 No-RAG 答案 vs RAG 答案 both-correct / both-wrong / conflicting 切分，报 conflicting 子集上选对率，这正是评估 CorroborationReranker「demote lone counterfactual」能力的现成协议；(3) **worst-case 协议**（RGB，全负例 top-5）作为我们 NIAH 极端配置的先例引用。结论层面可引用：真实检索下 ~70% passage 不含真答案、conflict 案例中 internal/external 各对 47.4%/52.6%——用来论证单靠多数票或单靠 parametric 都不够，必须 blend。
- **精确实验协议**：Dataset = 自建 1,042 条 short-form QA（NQ + TriviaQA + BioASQ + PopQA），检索 = **Google Search 真实检索**（top-30 取前 10 个可访问网页，抽 snippet 对应段落），每题 10 passages；另有 ASQA（long-form）和 RGB 英文精炼子集（每题选 top-5 negative passages 构造 worst case）。Models = Claude 3.5 Sonnet (20240620)、Gemini 1.5 Pro (002)、Mistral-Large 2407 (128B)、Mistral-Nemo 2407 (12B)；temperature=0，max 1,024 tokens，zero-shot。方法超参：默认 t=1（consolidation 迭代次数）、m̂=1（最多生成的 internal passage 数）。Metric = string-match accuracy（要求模型把答案包进 `<ANSWER>` 标签再抽取）；中间步骤用 LLM-as-a-judge 评 consolidation/confidence 正确率。粒度：passage 级 grouping，非逐句。
- **我的做法哪里不同**：机制上 Astute 是**纯生成端**方案——所有 conflict resolution 都发生在一个 LLM 的 in-context consolidation prompt 里（聚类一致信息、分离冲突、按 source+frequency+thoroughness 选最终答案），信号是隐式的、不可分解的；我们把同一直觉（cross-source consistency + parametric 一票）**下沉到 reranker**，corroboration 分数是显式算术（normalized answer 的 other-source 计数），可与 relevance 做 minmax convex blend 并离线 lambda-sweep，且改变的是 top-k 排序（needle-found@k/MRR）而非最终答案串——两者正交可叠加。另外它的 internal knowledge 是 adaptive 生成的完整 passage（Genread 风格），我们只取一个 parametric short answer 作为一票；它无 reranking 阶段概念，第一阶段检索固定为 Google Search。
- **reviewer 会攻击哪一点**：最锋利的攻击是「Astute RAG 证明生成阶段的 in-context consolidation 已经能在 conflicting 子集上 ~80% 选对，你的 rerank 阶段干预的增量价值是什么？」——我们必须给出 rerank-only vs generation-only vs both 的消融，并强调检索指标（needle-found@k）是 consolidation 无法修复的（needle 不进 top-k 就没有然后）。第二攻击点：我们的 corroboration 是频次投票，而 Astute 明确警告 frequency 只是 reliability 的信号之一（其 pans prompt 综合 source/credibility/agreement）；若干扰项在语料中重复出现（correlated misinformation），我们的投票会放大错误——需在 NIAH 里加多副本反事实的压力配置。这篇自身弱点：仅 string-match accuracy、1K 规模、无显著性检验、自己承认依赖强 instruction-following 模型（Limitations），且大量效果由未消融的 prompt 工程承担。
- 
**关键数字**：① 真实 Google 检索下约 70% passage 不含真答案；Claude 上 19.2% 样本出现 knowledge conflict（Fig. 1/2，Sec. 3）；② conflicting 案例中 internal knowledge 对 47.4%、external 对 52.6%（Sec. 3）；③ 主表 Claude overall：Astute 61.7 vs 最强 baseline InstructRAG 58.8、RAG 55.5、No RAG 54.5（Table 1；相对最佳 baseline +6.85%）；④ RGB worst-case 下 plain RAG 落后 No RAG 超过 50 点，Astute 是唯一接近 No RAG 的方法（Fig. 6）；⑤ source-awareness 消融：59.2 → 58.6（去掉 source 标签，Gemini，Table 3）；中间步骤 LLM-judge：consolidation 98.2%、confidence 95.0% 正确。

## #20 Wu et al. 2024 — ClashEval: Quantifying the tug-of-war between an LLM's internal prior and external evidence (NeurIPS 2024 D&B)

- **能复用什么**：这是我们计划 (b)（token-probability 校准加权 parametric 票）的直接方法来源：**Calibrated Token Probability Correction**——比较 r(q)（无 context）与 r(q|c) 的 mean token probability 的 **percentile**（而非原始值，因为 context-given 概率分布严重右偏、prior 概率近均匀，二者 uncalibrated），谁高用谁——可直接改造成我们 parametric vote 的权重 w = calibrated confidence。指标体系也可整体搬走：Accuracy / **Prior Bias** / Context Bias 的条件概率定义（Sec. 3.1）可映射为我们 reranker 的「needle 在 prior 错时被找回率」与「counterfactual 在 prior 对时被顶上率」。扰动设计（数值乘子 0.1–10×、年份 ±100、类别 slight/significant/comical）是构造分级难度 counterfactual needle 的现成配方。
- **精确实验协议**：Dataset = ClashEval，1,294 题、6 域（Drug Dosage 249 / News 238 / Wikipedia Dates 200 / Sports Records 191 / Names 200 / Locations 200，Table 1），题目和扰动 excerpt 均由 GPT-4o 生成并做 GPT-4o 质检；数值域每题 10 级扰动（乘 0.1/0.2/0.4/0.8/1.2/1.5/2/3/5/10），年份 ±100 每 20 年一档，Names/Locations 3 级类别扰动。Models = GPT-4o、GPT-3.5-turbo-0125、Llama-3-8B-Instruct、Claude Opus、Claude Sonnet、Gemini 1.5 Flash；prompt 用 LangChain/LlamaIndex 风格标准 RAG 模板（另测 strict/loose 变体，Fig. 6）。主实验 **k=1 单文档** context；附录做了 k=5（按 embedding cosine 加 4 篇）。判定 = 答案串匹配（限定格式：YYYY 年份、first+last name、去州名城市），粒度为整题级。confidence = 无 context 回答的 token 平均概率，分 10 个等距 bin。
- **我的做法哪里不同**：ClashEval 研究的是**生成端单文档仲裁**（prior vs 一篇被扰动的 gold 文档），我们是**检索端 20 候选投票**——机制差异在于我们不要求模型二选一，而是让 corroboration 计数天然稀释单个 counterfactual（它的 k=5 实验已经暗示多文档能降 context bias，我们把这个效应做成显式打分）。其扰动文档是对 gold excerpt 的合成改写，我们的 "Source-A" 干扰项是从真实语料挖掘的，表面分布更自然、无 GPT-4o 改写伪影。我们当前 parametric 票是二值一票，无 confidence 加权——这正是按它升级的空间；升级时注意它的关键发现：校准必须按 percentile 做，且各域 prior 分布差异大（GPT-4o mean prior prob 从 News 0.469 到 Locations 0.877，Table 5），Granite 4.1-3b 的 logprob 校准性未知，需要先复现它的 Fig. 4 斜率图。
- **reviewer 会攻击哪一点**：若我们引用它来支撑 calibrated parametric vote，reviewer 会指出：(1) 它的校准增益以 **prior bias 上升为代价**（GPT-4o 0.021→0.085，Table 3）——映射到我们场景就是校准票会压制真 needle（当模型自信地记错时），必须报双向错误而不是只报 needle-found@k；(2) 它的结论「deviation 越离谱 context 越不被采纳」意味着 plausible 的反事实（我们从真实语料挖的那种恰恰最 plausible）是最难防的区域，我们不能只在 comical 级干扰上报胜利；(3) 3B 小模型 logprob 校准可能远差于 GPT-4o（它只在提供 logprob 的三个模型上验证）。这篇自身弱点：全部 QA 由 GPT-4o 生成又部分由 GPT-4（o）作答，存在 self-preference 循环；纯事实型单跳问题；作者自己声明 error 率是 enriched 的、不代表真实分布；主实验 k=1 与真实 RAG 场景脱节。

**关键数字**：① GPT-4o 在 prior 正确而 context 错误时仍采纳 context 60.8%（context bias 0.304 全场第二差，Table 2/4）；② Claude Opus 全面最佳：accuracy 74.3%、context bias 15.7%、prior bias 2.1%（Table 4）；③ Calibrated Token Prob. Correction 把 GPT-4o accuracy 0.615→0.754、context bias 0.304→0.107，但 prior bias 0.021→0.085（Table 3）；同偏差率下随机替换 baseline 只有 57.5% vs 方法 75.4%；④ prior token probability 每 +10%，context 采纳率降 1–4.5%（斜率 -0.1 至 -0.45，Fig. 4）；⑤ k=1→k=5 多文档：GPT-4o context-correct 采纳 0.903→0.868、prior-correct 时误采 context 0.582→0.383（Table 7）。

## #7 Saxena et al. 2025 — Generation-Time vs. Post-hoc Citation: A Holistic Evaluation of LLM Attribution (NeurIPS 2025 Workshop)

- **能复用什么**：最有用的是 **Finding 3 作为立论引用**："retrieval augmentation is the primary driver of citation accuracy"（FEVER 上 G-Cite correctness 27%→77% 仅靠加 RAG）——这直接支撑我们「把 faithfulness 防御做在检索侧」的定位叙事，即 citation 质量的上游瓶颈是检索质量。其次是 G-Cite/P-Cite 二分法框架 + 五指标体系（Citation Precision / Recall / Correctness=调和平均 / Coverage / Latency）可作为我们复现 ALCE citation P/R 时的 metric 命名与计算规范（precision/recall 定义对齐 Aly et al. 2024）；其 RAG pipeline（SBERT bi-encoder + cross-encoder reranker）是我们对比时的标准两阶段配置。human eval 设计（100 instances/method-dataset、2 annotator、κ、80% power 检测 d≥0.5）可作为小规模人评的规模论证模板。
- **精确实验协议**：Datasets = ALCE 3,000（open-domain QA，doc+sent 级，G-Cite native）、LongBench-Cite 1,000（长上下文，sent 级）、REASONS 12,723（科学引文，P-Cite native）、FEVER 185,445（claim 级事实核查）（Table 1），并做 cross-paradigm 适配（如 ALCE 先产 citation-free draft 再让 P-Cite 贴引用；REASONS 的 G-Cite 用受限候选池改写）。Model = **LLaMa-3.1-8B-Instruct 统一所有方法**（除 CiteBART 用 BART）；方法四类：Zero-shot、Fine-tuned（LongCite-8B、CiteBART）、RAG（SBERT + cross-encoder rerank）、Advanced（G: CoT Citation；P: CEG 迭代检索+逐条 verify）。解码 temperature=0.2、top_p=0.95、max_new_tokens=256，citation 用严格 regex 解析。判定器：指标为与 ground-truth citation 的匹配（非 NLI）；human eval 报 Answer Correctness（全部 claim 有支撑记 1）与 Citation Hallucination（引用不在 ground-truth 集合记 1），κ=0.873。
- **我的做法哪里不同**：它评估的是 attribution 附着环节（答案已定，问 citation 贴得对不对），我们干预的是更上游的 candidate ranking——我们的 corroboration 信号相当于在检索阶段就预筛出「能被多源 entail 的答案载体」，这是它框架里两个 paradigm 都不覆盖的第三个位置（retrieval-time evidence selection）。粒度差异：它 doc/sent/claim 级 citation 对 ground-truth 集合匹配，我们是 passage 级 + normalized short answer 的等价类投票，无 citation 标注需求，因此能跑在无 gold-citation 的 NIAH 语料上。我们计划的 ALCE 复现要注意：它没有做 masking-and-recovery / faithfulness 类因果测试（与 Wallat 互补），其 citation correctness 只是 P/R 调和平均，不检验 causal reliance。
- **reviewer 会攻击哪一点**：若我们引它论证「检索质量决定 attribution 质量，所以改 reranker 就是改 faithfulness」，reviewer 会反驳这是**必要非充分**——它测的是 citation 与 ground truth 的匹配率，不是 Wallat 意义上的 faithfulness，我们不能把两个概念混用（应写成 retrieval 提升 attribution 的 correctness 上限，faithfulness 需另测）；且既然 retrieval 是主驱动，reviewer 可能要求证明 corroboration rerank 优于「更强的普通 rerank」（如 cross-encoder），即增益来自 corroboration 信号而非 rerank 本身。这篇自身弱点很多、引用需谨慎：workshop 短文无显著性检验；ALCE 上 Zero-shot (P) 出现 precision=1.000、correctness=0.881 远超所有 RAG/Advanced 方法（Table 2），明显是其 References-block regex 协议的 artifact；非 native paradigm 的数据集适配可能系统性偏袒某一方；CiteBART 多数格子缺失（—）；latency 未说明硬件。

**关键数字**：① FEVER：Zero-shot→RAG 使 G-Cite citation correctness 0.272→0.769（约 +50pp，Finding 3 / Table 4）；LongBench-Cite G-Cite coverage 0.112→0.577；② FEVER 上 CoT Citation (G) correctness 0.937、precision 1.000 但 coverage 仅 0.272，CEG (P) correctness 0.766、coverage 0.744（Table 4）——precision/coverage 权衡的最典型例证；③ ALCE：Advanced P-Cite (CEG) coverage 0.748 / correctness 0.422 vs Advanced G-Cite (CoT) 0.372 / 0.205（Table 2，正文 Finding 1 取整为 75%/42% vs 37%/21%）；④ human eval：P-Cite answer correctness 78% vs G-Cite 69%，citation hallucination 37% vs 41%（Fig. 2，κ=0.873）；⑤ 异常值警示：ALCE Zero-shot (P) citation correctness 0.881、precision 1.000（Table 2），高于同数据集所有其它方法，疑为评测协议 artifact。
